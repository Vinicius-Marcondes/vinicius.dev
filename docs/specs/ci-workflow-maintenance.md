# CI Workflow Maintenance

## Purpose
Define a narrow CI maintenance slice that restores analyzer freshness validation after repository cleanup and updates workflow action usage for the GitHub Actions Node.js 24 transition.

## Scope
- analyzer freshness enforcement for the tracked frontend analyzer report
- GitHub Actions workflow maintenance needed to remove the current missing-report failure
- Node.js 24 compatibility updates for JavaScript-based GitHub Actions used by repo workflows
- minimal harness alignment needed to keep workflow behavior and tracked artifacts consistent

## Locked Decisions
- `docs/specs/frontend-analyzer-report.md` remains the tracked analyzer freshness artifact for the current CI policy.
- `scripts/frontend-analyzer.ts` remains the canonical generator for that tracked report.
- `.github/workflows/analyzer-freshness.yml` remains a non-mutating validation workflow that compares a temporary generated report against the tracked report.
- This maintenance slice restores the tracked-report contract instead of removing analyzer freshness from CI.
- Workflow runtime maintenance must prefer upgrading action versions over relying on temporary GitHub Actions compatibility flags.
- Shared workflow changes in this slice are limited to Node.js 24 compatibility and the analyzer freshness contract; trigger policy, deploy policy, and validation scope remain unchanged unless a minimal fix is required.
- No frontend or backend product behavior changes are included.

## Interfaces and Responsibilities
- `docs/specs/frontend-analyzer-report.md`
  - exists in the repository as the tracked baseline used by analyzer freshness validation
  - is regenerated by `bun scripts/frontend-analyzer.ts` when frontend analyzer output changes
- `scripts/frontend-analyzer.ts`
  - keeps the current report output contract
  - remains responsible for writing the tracked report when run without an override path
- `.github/workflows/analyzer-freshness.yml`
  - generates a temporary analyzer report during CI
  - verifies that the tracked report exists
  - compares tracked and generated output while ignoring volatile timestamp metadata
  - fails on real analyzer drift, not on missing workflow wiring
- `.github/workflows/pr-validation.yml`
- `.github/workflows/branch-validation.yml`
- `.github/workflows/backend-boundary-architecture.yml`
- `.github/workflows/persistence-migration-validation.yml`
- `.github/workflows/production-deploy.yml`
  - upgrade JavaScript-based actions to Node.js 24 compatible releases where available
  - preserve current triggers, permissions, concurrency, and validation intent

## Data/Contracts Touched
- tracked analyzer report path: `docs/specs/frontend-analyzer-report.md`
- analyzer freshness workflow comparison contract
- GitHub Actions action-version references
- GitHub Actions Node.js runtime compatibility behavior

## Acceptance Checklist
### Functional acceptance
- [ ] `docs/specs/frontend-analyzer-report.md` exists again as a tracked repository file.
- [ ] Running `bun scripts/frontend-analyzer.ts` without `--output` writes the tracked report to `docs/specs/frontend-analyzer-report.md`.
- [ ] `.github/workflows/analyzer-freshness.yml` no longer fails solely because the tracked report file is missing.
- [ ] Analyzer freshness still fails when the tracked report drifts from the generated report.
- [ ] Workflow maintenance does not relax the existing analyzer freshness policy.

### Data/integration acceptance
- [ ] The tracked analyzer report path remains `docs/specs/frontend-analyzer-report.md`.
- [ ] All workflow files using `actions/checkout` are updated to a Node.js 24 compatible release.
- [ ] Temporary compatibility flags are added only if an upgraded required action still needs them after version updates.
- [ ] Workflow trigger scope and merge-gate intent remain aligned with `ci-cd.md`.

### Operational acceptance
- [ ] The maintenance slice can be verified locally by regenerating the analyzer report and reviewing workflow YAML diffs.
- [ ] No deployment trigger, VPS secret contract, or production tag policy changes are introduced.
- [ ] The fix remains isolated enough to revert without bundling unrelated frontend or backend changes.

### Explicit non-goals or exclusions
- [ ] No analyzer algorithm redesign is included.
- [ ] No removal of analyzer freshness from CI is included.
- [ ] No frontend or backend application code changes are included.
- [ ] No CI trigger-matrix redesign or deployment-policy redesign is included.
