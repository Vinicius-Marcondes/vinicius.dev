# PRD-002 - Admin Dashboard Control Deck Restyle

## Status
Ready

## Summary
Restyle the existing admin dashboard screen so `/admin/dashboard` matches the control-deck visual direction, layout density, and CRT effects from `references/vinicius.dev.v2/dashboard.html` while preserving all current admin dashboard data loading, chat room password rotation, auth redirect behavior, and adjacent admin photo workflows.

## Goals
- Make `/admin/dashboard` visually match the reference control deck: sticky admin nav, channel-style bug, compact page header, four stat cards, content queue panel, now-playing panel, chat room access panel, CRT scanlines, glitch hover, blink/pulse states, and hard rectangular surfaces.
- Preserve the current backend-connected dashboard summary, content queue rendering, room access display, and room password rotation flow.
- Keep the admin photo listing, upload, detail, metadata edit, curation edit, pagination, filters, and backend connections working exactly as they do today.
- Use the Vinicius.Dev design system rules and tokens from `.agents/skills/vinicius-dev-website-guidelines/`, especially rectangular geometry, three-font typography, restrained neon, CRT texture, and reduced-motion support.
- Allow limited shared component or global CSS changes only when they are necessary to reuse or align existing admin shell/shared UI components with the requested dashboard style.

## Non-Goals
- Do not change backend APIs, database schema, Prisma models, auth behavior, chat room semantics, media handling, or deployment configuration.
- Do not redesign public pages.
- Do not redesign `/admin/photos`, `/admin/photos/upload`, or `/admin/photos/:id` beyond incidental shared-component styling required to preserve consistency and functionality.
- Do not add new admin capabilities, new photo editing fields, new moderation features, or new status-strip editing behavior.
- Do not create broad visual-regression infrastructure or introduce a new UI framework.

## Context
The current admin dashboard already works through React Router loader data from `getAdminDashboardSummary`, room access data from `getChatRoomAccess`, and password rotation through `rotateChatRoomPassword('night-shift', {})`. The reference file `references/vinicius.dev.v2/dashboard.html` defines the desired screen composition and interaction language, but production code must stay inside the existing React 19 + Vite + TypeScript frontend and strict Feature-Sliced Design boundaries.

The admin photo surfaces are already functional and must remain functional. This PRD treats `/admin/dashboard` as the implementation target and treats `/admin/photos` flows as regression-sensitive adjacent surfaces. If a shared admin shell, global CSS token, or shared UI primitive must change, the change must preserve existing photo listing and editing behavior.

The canonical design source remains `.agents/skills/vinicius-dev-website-guidelines/`. If the reference HTML conflicts with the canonical brand rules, the implementation should keep the reference intent while following the design system unless Vinicius explicitly approves an exception.

## Requirements
- The dashboard route must remain `/admin/dashboard` and continue using the existing loader, view model, and auth redirect behavior.
- The dashboard must render live backend-provided panel values and queue items; static sample data may remain only as the existing empty/fallback state behavior.
- Password rotation must keep calling the existing chat room rotation API, update displayed room access state after success, expose errors, and keep the button disabled while rotation is in progress.
- The dashboard page must adopt the reference layout structure: top admin shell navigation, compact page header, four stat cards, a large content queue panel, and a right column containing now-playing and chat room access panels.
- Dashboard styling must use the Vinicius.Dev tokens and rules: near-black backgrounds, Fira Mono body/UI, VT323 non-wordmark headings and counters, Press Start 2P only for the `vinicius.dev control` wordmark, rectangular corners, hard borders, hard offset blocks where appropriate, and no emoji.
- CRT effects must include scanlines, restrained glitch hover, blinking/pulsing live state, and reduced-motion fallbacks.
- The implementation must not introduce rounded UI, glassmorphism, soft blurred shadows beyond approved glow tokens, unsupported fonts, broad gradients outside allowed contexts, or marketing copy.
- Shared components or global CSS may be changed only when needed for the admin dashboard restyle or to reuse already-developed components that match the requested style.
- Admin photo listing and editing workflows must remain connected to the backend and must not regress because of shared CSS/component changes.
- Existing frontend tests around the admin dashboard and admin photo pages must be updated or preserved so they validate current behavior after the restyle.

## Implementation Overview
First, map the reference HTML into production React structure without changing route boundaries or backend-facing code. Then update dashboard-specific markup and CSS classes to express the stat cards, queue rows, information panels, rotation button, toasts/errors, and responsive layout. If necessary, make tightly scoped shared admin shell or shared UI primitive styling changes so the dashboard can reuse existing components without harming other admin screens. Finally, verify dashboard behavior and photo admin regressions through focused frontend tests and a production build.

## Acceptance Criteria
- [ ] `/admin/dashboard` visually follows `references/vinicius.dev.v2/dashboard.html` for layout, density, panel hierarchy, typography, borders, CRT scanlines, glitch hover, live/blink states, and responsive behavior.
- [ ] The dashboard still renders backend-provided summary panel values and content queue items from the existing loader/view model.
- [ ] The dashboard still redirects unauthenticated users to `/admin/login` through the existing loader behavior.
- [ ] Chat room access still displays the current room slug, current password or generated-empty state, rotation status, session TTL, and revoked-session count when available.
- [ ] Room password rotation still calls the existing backend API, disables the control while pending, updates displayed state after success, and shows a failure message on error.
- [ ] `/admin/photos`, `/admin/photos/upload`, and `/admin/photos/:id` still list photos, upload photos, display originals, edit metadata, edit curation, filter, and paginate using their existing backend connections.
- [ ] Any shared component or global CSS changes are justified by dashboard reuse and do not broadly redesign unrelated surfaces.
- [ ] The implementation follows the Vinicius.Dev design system: no rounded UI, no emoji, no glassmorphism, no unsupported fonts, no unapproved color tokens, and reduced-motion handling for animations.
- [ ] Focus states remain visible and keyboard navigation remains usable for nav links, queue links/actions, form fields, and the room password rotation control.
- [ ] Frontend verification passes at minimum for admin dashboard tests, admin photo page tests, lint, and build.
